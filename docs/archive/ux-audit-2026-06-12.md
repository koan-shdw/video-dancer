# vi-dancer — UX / Workflow / UI Mega-Audit

*2026-06-12 · pre-beta. Scope: how the app works, where the workflow rubs, and every UI inconsistency — ending in a prioritized cleanup list for the first beta port. Method: full read of every panel + two systematic inventories (icons/buttons, colors/typography). Report only — nothing here is built yet.*

---

## A. How the app works today (macro map)

### Surfaces

| Panel | Role | Opens via |
|---|---|---|
| **Header** | New/Open project, ⛶ max, Settings, workspace switcher, FAL credit chip | always |
| **Library** | reference images (@titles, folders) + ♪ music | default layout |
| **Bin** | clips (tiles), timelines (▤ cards), cross-project import | default layout |
| **Clip Editor** | the recipe: prompt, fields, beats, refs, engine/res/duration, RENDER, takes strip | default; raised by timeline dbl-click |
| **Timeline Monitor** | program player on the timeline-aspect canvas; 📷 grab | default |
| **Clip Monitor** | source player: in/out trim, beats bar+editor, 📷 | tabbed w/ monitor; raised on preview-target change |
| **Timeline** | transport, mutes, ✂ slice, blocks (filmstrip/scrub-frame, trims), audio lane, ⬆ export | default |
| **Timeline Editor** | name, aspect, EXPORT (res/fps/button) | Bin timeline dbl-click |
| **Image Editor** | Nano Banana edit/generate + persisted results tree | Library image dbl-click |
| **Settings modal** | BYO keys (fal, fal admin, Astria, Anthropic) | header |
| **prompt.tsx dialogs** | textPrompt / confirmDialog | everywhere |

### The core loop

```
import refs (Library) ──► author recipe (Clip Editor: prompt+@refs+beats)
        ▲                          │ RENDER ($, fal)
   Image Editor                    ▼
   (Nano Banana tree)         takes (frozen snapshots)
                                   │ drag / dbl-click
                                   ▼
                       timeline (instances: take or C·live)
                       trim · slice · reorder · music lane
                                   │ ⬆ EXPORT (ffmpeg)
                                   ▼
                                 mp4
```

This loop is **sound** — the take/C model, per-slot trims, snapshot immutability, and one-recipe-per-clip are coherent and now battle-tested. The friction is almost all in the *connective tissue*: keyboard, feedback, naming, and visual consistency.

### Interaction grammar as built

| Gesture | Bin clip | Bin timeline | Library image | Library ♪ | TL block | TL music | Take chip |
|---|---|---|---|---|---|---|---|
| click | select | activate | — | — | playhead | (exp.) cycle view | preview |
| dbl-click | **nothing** | TL Editor | Image Editor | **nothing** | Clip Editor | waveform | — |
| drag | →timeline/folder | — | →prompt/slots/folder | →audio lane | reorder | move | →fields/bin/timeline |
| right-click | menu | menu | menu | (✎/🗑 inline) | — (take ▾ menu) | — | — |

Grammar is *mostly* consistent (dbl-click = "open the editor for this thing") with two holes: **Bin clip dbl-click does nothing** (should open Clip Editor — it's the #1 expectation) and ♪ rows have no dbl-click (could preview/play).

## B. Workflow audit — stage by stage

### B0. First run / onboarding — *the weakest stage*
- **F1.** A new user's mandatory first step is pasting a fal key, but nothing says so. The failure arrives later, at render time, as a status-line string ("No fal key saved — paste it in Settings first."). Beta testers WILL hit this. Needs a first-run check: no key → banner or welcome card pointing at Settings.
- **F2.** No project → each panel shows its own hint; fine, but there's no single "do these 3 things" empty state (1. set key · 2. New project · 3. import refs / + New clip).
- **F3.** All discoverability is tooltips + one hint line under the timeline. The drag-drop vocabulary (clip→timeline, take-chip→fields, image→prompt, ♪→lane) is invisible until known. One `?` **shortcut/gesture cheat-sheet overlay** would carry the whole app.

### B1. Project
- Works: auto-open last, atomic saves, undo/redo. 
- **F4.** No recent-projects list (only "last"). Open dialog = pick a folder, no validation feedback until after.
- **F5.** Undo/redo have **zero visible feedback** — project mutates silently under you. A 1-line toast ("undid: timeline change") would build trust. Also: Ctrl+Z is undocumented anywhere in-app.

### B2. References (Library / Image Editor)
- Works: @title model, folders, drag-to-prompt inserting @name, rename rewrites mentions everywhere, results tree.
- **F6.** Import gives no completion feedback (images just appear; on a big import nothing says "12 imported").
- **F7.** ♪ rows: rename/delete are hover-buttons while images use right-click menus — same panel, two interaction systems.
- **F8.** Image Editor canvas has no zoom/pan (known, Phase 2) and the editor's own prompt box doesn't get the rename @-rewrite (known, low-stakes).

### B3. Clip authoring (Clip Editor)
- Works: prompt+@mention autocomplete, fields expander, per-field 🔗 links, beats, T-chip restores, lint/cost line.
- **F9.** It's one tall form — prompt, link chips, fields, beats, refs, frames, settings, render, takes. No section landmarks; on small panels the RENDER button can be off-screen. Needs grouped/sticky structure (the ui_style "collapsible SETUP" pattern from KOAN.img, which this app never got).
- **F10.** "C" and "take N" jargon is explained only in tooltips. One "what's C?" hint at the takes strip would do it.
- **F11.** Status line (`setStatus`) is the only render feedback; if the panel is hidden/tabbed, a render finishing is invisible. Render-done deserves an app-level toast.

### B4. Takes
- Works: frozen snapshots, keeper, per-slot takes, durations backfilled.
- **F12.** No per-instance (clip) audio mute/gain — only the timeline-level 🎬 mute. The export research flagged this as "not optional": first mixed Sora(audio)+Seedance(silent) timeline, users will want "shut THIS clip up." (Tier-1 adjacent, P1.)

### B5. Timeline assembly
- Works: proportional blocks, filmstrips + scrub-frame, trims with snap + preview frame, ✂ slice w/ snap, reorder, takes menu, multi-timeline.
- **F13.** **No keyboard transport.** Space doesn't play/pause; no ←/→ nudge, no Del-remove, no I/O set-trim, no Home/End. For an NLE-shaped tool this is the single biggest feel gap. (S, Esc, Ctrl+Z exist — already half a system.)
- **F14.** No selection state on blocks distinct from the playhead — block click = playhead move only, so Del-to-remove has nothing to bind to. ✕ on the block is the only removal.
- **F15.** No timeline zoom: long timelines compress blocks to the 44px minimum; a 30-clip sequence will be unusable. (Flex-proportional layout needs an h-zoom factor.)
- **F16.** Drop always appends at the end (reorder after). Insert-at-position via drop indicator would match expectation, but append+reorder is liveable for beta.
- **F17.** The hint line under the timeline is the only mention of S/slice/snap — overloaded (see F3 cheat-sheet).

### B6. Music
- Works: lane, drop-at-cursor, move/trim, head-trim sync, waveform/beats view, layer mutes, playback sync.
- **F18.** Music block click-cycle/waveform exists, but beat ticks aren't yet snap targets for slice/trims (flagged follow-up — the payoff feature).
- **F19.** No music volume — mutes only (accepted v1 ruling; gain slider is the obvious P2).

### B7. Export
- Works: settings in TL Editor, both buttons, live %, save dialog, verified output.
- **F20.** Export-done message shows a path truncated to 48 chars in the toolbar; no "open folder" action. One click-to-reveal (shell.showItemInFolder) closes the loop.
- **F21.** Export errors (ffmpeg stderr tail) also truncate in the toolbar; full text only in TL Editor. Toast + expandable detail.
- **F22.** No estimated file size / duration on the export section (research sheet had "Est. ~48 MB" — cheap: dur × bitrate guess).

## C. Systemic UX findings

1. **Keyboard is the missing limb** (F13). Proposal — global, when not typing:
   `Space` play/pause · `←/→` prev/next clip (Shift = nudge playhead) · `Home/End` start/end · `Del` remove selected block · `S` slice (exists) · `M` mute music · `Ctrl+E` export · `?` cheat-sheet. All trivially routed through the existing App-level key handler.
2. **Feedback is fragmented across 5 status surfaces** — RenderPanel status line, export msg (toolbar + TL Editor), grabMsg overlays (×2 monitors), Settings "saved ✓", and silent operations (import, undo, delete). **One toast system** (bottom-center, 2.5s, queue of 3) absorbs: render done/error, export done/error+reveal, import counts, undo/redo, frame-grab ✓, key saved. Panel-local status lines stay for *live* progress only.
3. **confirmDialog is mis-shaped**: its confirm button is hardcoded **"Delete"** — but it's used as a plain alert in at least two places (Bin: "No readable project…", Library: "@title already taken"), so users must click **Delete** to acknowledge info. Needs `confirmDialog(msg, {confirmLabel, danger})` + a separate `alertDialog`.
4. **Destructive consistency**: clip/timeline/image deletes confirm only when "in use"; audio delete confirms only when on a timeline; branch delete (🗑 in Image Editor) confirms; timeline block ✕ never confirms (fine — undoable); but none of them mention **Ctrl+Z exists**. One standard: destructive confirms say "(undoable with Ctrl+Z)".
5. **Dbl-click grammar holes**: Bin clip → should open Clip Editor (the one inconsistency users will feel in minute one).
6. **Naming drift**: panel id `render` titled "Clip Editor"; "C · recipe"/"C — live recipe"/"C (live recipe)" written three ways; "take N / M" vs "tN" in Bin labels. Pick one phrasebook.
7. **Settings is stale**: Astria key labeled "image gen / edit (Nano Banana)" — but Nano Banana runs through **fal** now; Anthropic key is unused ("Claude prompt brain" doesn't exist yet). Two dead fields in the FIRST modal a beta tester opens. Relabel section to "not used yet — future features" or hide.

## D. UI consistency findings (from the inventories)

### D1. Icons — collisions and gaps
- **⬆ collision (worst):** "⬆ import image" (Library) vs "⬆ export mp4" (TL Editor) vs ⬆ toolbar export vs "⇪ Import from project…" (Bin). Same family of arrows pointing the same way for opposite data directions.
- **🔊/🔇 overload:** Clip Monitor mute, video-layer mute (🎬-prefixed), music mute (♪-prefixed) — prefixes save it on the timeline, but the Clip Monitor's bare 🔇 means a *different* scope than the timeline's pair.
- **▶ triple duty:** play control, "has render" badge (Bin/blocks), import-dialog thumb placeholder.
- Inventory: ~40 glyphs; the rest are consistent (✎ ⧉ 🗑 ✕ ★ ▾/▸ families are clean).

### D2. Buttons — 5 archetypes, no system
`btn` (amber primary) / `btn vd-hbtn` (header/panel chip) / `vd-slot` (pill toggle) / `vd-loop` (transport icon, opacity-state) / bare clickable span-divs (menus, take picker, workspace menu, ✕s). Same action class styled differently across panels (close buttons alone appear 3 ways). 

### D3. Tooltips
All `title=` (OS-delayed, unstylable). No casing/separator standard (`·` vs `—` vs `→` vs `\n`), lengths 1 word→162 chars. Fine for beta IF standardized: lowercase fragments, `·` separators, lead with the primary gesture.

### D4. Color
- Tokens exist (`--amber --dim --line --panel`…) but **~35 unique colors in use, 46% token coverage**: `#16161a` hardcoded 9× (≡ --bg2), `#e8e8ee` (18×) and `#cfcfd6` (8×) are unofficial text tiers, `#ff5a5a` is an unofficial danger/armed/red distinct from `--bad` (#e0795f) — **two different reds** mean "danger" in different panels.
- Semantic overloading: red = errors AND armed-slice AND muted; amber = accent AND selection AND snap AND warnings. Green now = music + success. Needs a declared semantic map (accent / selection / danger / armed / muted / music) even if some share a hue.
- `ctl` (shared input style) hardcodes its border `#33333c` instead of `var(--line)`.

### D5. Typography & spacing
- **11 font sizes** (8→26): consolidate to ~5 steps (9 label / 10 small / 11 body-sm / 12 body / 15 title).
- Spacing: 15 values in use; informal 4/6/8 system already dominates — formalize `spacing = {2,4,6,8,12,16}` in tokens.
- 12 of 22 components bypass `ui/controls`+tokens entirely (SourceMonitor, Bin, Timeline, Monitor, Library, modals…).

### D6. Panel chrome & empty states
Empty states exist and are good (Bin, Library, monitors, lane); section headers (`9px uppercase letter-spaced`) are consistent where used — they're an emerging standard worth blessing. Modals (Settings / Workspaces / import picker / prompt.tsx) share the look by accident, not by component: one `<Modal>` shell would lock it.

## E. Icon plan — unique icon per action

**Recommended: adopt `lucide-react`** (one dep, tree-shaken SVGs, uniform 1.5px stroke, sizes locked to 14/16px). Emoji render OS-dependently (Windows color emoji vs the mono glyphs mixed in) and can't be styled/colored consistently — the app already mixes color emoji (🎨🗑📷) with text glyphs (✎ ⧉ ▾), which is half the "inconsistent" feel.

| Action | Now | Proposed (lucide) |
|---|---|---|
| import image / music | ⬆ / ♪ | `ImageDown` / `FileMusic` |
| export mp4 | ⬆ | `Upload` (or `Clapperboard`+`ArrowRight`) — **unique from import** |
| import from project | ⇪ | `FolderInput` |
| new clip / new image | + / ✨ | `Plus` / `Sparkles` |
| edit with AI | 🎨 | `Wand2` |
| rename / duplicate / delete | ✎ ⧉ 🗑 | `Pencil` `Copy` `Trash2` |
| play/pause/prev/next/loop | ▶⏸⏮⏭⟲ | `Play Pause SkipBack SkipForward Repeat` |
| slice | ✂ | `Scissors` |
| filmstrips | 🎞 | `Film` |
| clip-audio mute / music mute | 🎬🔇 / ♪🔇 | `Clapperboard`+`VolumeX` / `Music`+`VolumeX` (stacked badge) |
| frame grab | 📷 | `Camera` |
| maximize / restore | ⛶ 🗗 | `Maximize2 Minimize2` |
| settings / link / waveform | ⚙ 🔗 — | `Settings2 Link2 AudioWaveform` |
| timeline badge | ▤ | `ListVideo` |

Cheap interim (if icons wait): fix ONLY the collisions — import → 📥, keep export ⬆; Clip Monitor mute → prefix like the others.

## F. THE CLEANUP LIST (prioritized, pre-beta)

### P0 — beta blockers (testers hit these in the first hour)
1. **Space = play/pause** + minimal transport keys (←/→ clips, Home/End). *App.tsx key handler.*
2. **First-run fal-key check**: no key → persistent header banner "set your fal key → Settings". *App.tsx + settings.*
3. **confirmDialog button label** parameterized; stop using it as an alert (2 call sites). *prompt.tsx, Bin, Library.*
4. **Bin clip dbl-click → Clip Editor.** *Bin.tsx (+panelBus raise like timeline dbl-click).*
5. **Toast system** (one component) + wire: render done/error, export done/error, import counts, undo/redo. *new ui/Toast.tsx; ~6 call sites.*
6. **Export done → click to reveal file** (shell.showItemInFolder via IPC); full error text in the toast. *main + Timeline/TimelineEditor.*
7. **Icon collision fix** (at minimum import vs export; ideally the full lucide pass — see E). 
8. **Settings cleanup**: fix the Astria/Nano Banana mislabel; mark unused keys "future". *SettingsModal.tsx.*
9. **About box: FFmpeg attribution** (GPL notice + source link) + app version. Legally owed the moment a beta zip ships. *new modal, header.*
10. **App icon + productName in the installer** (currently default Electron icon). *build config + .ico.*
11. **`?` cheat-sheet overlay**: keyboard map + drag-drop vocabulary on one card. Carries onboarding until docs exist. *new modal.*

### P1 — consistency & flow (the "feels professional" pass)
12. lucide-react icon swap everywhere (E table). 
13. One `<Button kind="primary|chip|toggle|icon">` + one `<Modal>` shell; kill the 5 archetypes / 3 ✕ styles.
14. Design tokens: text tiers (bless #e8e8ee/#cfcfd6 as vars), ONE danger red, spacing scale, 5-step type scale; fix `ctl` border var; sweep the 9 hardcoded `#16161a`s.
15. Timeline selection model: click = select (visual ring) + playhead; `Del` removes; ✕ stays.
16. Timeline zoom (h-scale factor + scroll) — required before anyone builds a >10-clip sequence.
17. Per-instance clip-audio mute (+gain slider) on the timeline take menu / Clip Editor. *Research doc called it not-optional.*
18. Render/export status: when the Clip Editor is tabbed away, the toast (P0-5) covers it — also badge the tab (dockview API) while busy.
19. Clip Editor structure: collapsible groups (SETUP / PROMPT / BEATS / REFS / OUTPUT) + sticky RENDER row with cost. (Port the KOAN.img ui_style pattern.)
20. Tooltip standard: lowercase, `·` separators, lead gesture; sweep all titles once.
21. Naming phrasebook: "C — live recipe" everywhere; "take N/M" everywhere; rename internal `render` panel id at next layout-breaking change.
22. Undo/redo toast + list the shortcut in the cheat-sheet (P0-11).
23. ♪ rows: right-click menu like images (drop the hover-button special case).
24. Slice/trim snap to music beat ticks (the flagged follow-up — beats view exists, snap is the payoff).
25. Recent projects list (header dropdown next to Open).

### P2 — polish / later
26. Music gain slider + master volume; audio fade in/out handles on the lane.
27. Insert-at-drop-position on the timeline (drop indicator between blocks).
28. Export: estimated size, Draft preset (720p one-click), platform presets (the §E sheet from the export research).
29. Image Editor: canvas zoom/pan; rename @-rewrite for its live prompt box; Phase-2 drawing/guide tools.
30. Blur-pad mismatch option (research §B) + per-instance fit/fill override.
31. Transitions/crossfades between blocks (the WebGPU compositor roadmap).
32. OTIO/EDL export ("open in Premiere/Resolve") — strategic, parked.
33. Animated micro-interactions (drop highlights, toast slide) once the component layer (13) exists.

### Beta-port extras (not UX, owed before the zip)
- `electron-builder` smoke test on a clean machine (installer never run yet); unsigned-exe SmartScreen note in the README.
- Crash/error log file (main-process catch → userData/log.txt) so testers can send something.
- Beta README: the A-section macro map + cheat-sheet content + "you need a fal key, costs are yours" + known limits (no zoom, no per-clip gain).
- Version string surfaced in the header/About (currently 0.0.1 in package.json only).

## G. Macro verdict

The **model** (clips=recipes, takes=frozen, C=live, timelines=bin citizens, music=one lane, export=WYSIWYG) is the strongest part of the app — it's coherent, explainable in one diagram, and already validated by use. The gap to "beta-ready" is not features: it's **(1) keyboard, (2) feedback, (3) one visual system**. P0 list is ~2 focused sessions; P1 is the difference between "works" and "feels like a product."
