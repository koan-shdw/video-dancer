### Export baker — design (A4)

Goal: exported video pixel-matches the fx preview. Main already has the pipeline: `planExport`
(fx spans → ExportBake slots), `fx:bakeStart`/`fx:encodeFrame`/`fx:encodeEnd` (RGBA →
yuv420p segment via ffmpeg stdin), and `exportRun(timelineId, bakes)` splicing baked segments
between untouched take segments. Missing piece = the renderer loop that renders each fx span
frame-by-frame and streams pixels to main. (Assumption checked at build time: exact
planExport/ExportBake signatures as observed by the audit; adjust to reality, do not redesign.)

Renderer `bakeFxSpans(timelineId)` in a new `fx/baker.ts`:

1. `const plan = await vidancer.exportPlan(timelineId)` — spans list, each with items, source
   files, fps, W×H, in/out times.
2. Per span, sequential (no parallelism — GPU + decoder contention):
   a. Create offscreen `<canvas>` at span resolution + `createFxChain` (reuse the Monitor's
      chain module — same code path = parity by construction).
   b. Media: one hidden `<video>` per layer file (reuse the Monitor's player-pool approach),
      plus sidecars via existing sidecar loader when the stack needs matte/depth. Wait
      readyState ≥ 2 before frame 0 (kills the L6 shakedown-4 "pops in late" class in exports).
   c. Frame loop `t = span.start + k/fps`: seek each video to its source time, await
      'seeked' (Promise.all), render chain, `readPixels` into a reused ArrayBuffer,
      `vidancer.fxEncodeFrame(jobId, buffer)` (transferable). Honor backpressure: await each
      send (main already drains stdin).
   d. `fxEncodeEnd` → baked segment path; report `{spanId, file}`.
3. Progress: `exportState.phase = 'baking'`, per-span frame counter → existing export progress
   UI. Cancel: existing export cancel (B-package adds the IPC) also aborts the bake loop and
   calls `fxEncodeEnd(abort)`; .part cleanup already exists main-side.
4. Failure: any span failure → abort whole export with the error surfaced (no partial silent
   fallback — parity or nothing), leaving the hard-block rule available.
5. `startExport` passes the ExportBake[] list to `exportRun`. Color: main's bake encode gets
   the bt709 matrix flags (L6#8) so baked spans match take segments.

Determinism note: seek-based stepping is frame-accurate enough at 24fps with 'seeked' awaited;
WebCodecs frame-exact decode is the future upgrade, out of scope.

Acceptance (added to TEST-SHEET):
- Timeline A: one take, no fx → export byte-similar to previous exporter output (control).
- Timeline B: same take + opacity 50% stack → exported frames visibly match preview (spot-check
  3 frames vs Monitor screenshot).
- Timeline C: mask + soft edge over second layer → no halo, feather visible in export.
- Timeline D: fx span between two clean takes → no color shift at splice boundaries.
- Cancel mid-bake → no .part files, no orphaned ffmpeg, export UI resets.
