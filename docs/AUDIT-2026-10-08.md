# Video Dancer audit, 2026-10-08 (Opus)

Read-only. vi-dancer `627525f` + working tree, koan-shared `4b46f10`. Threat model: one person on their own PC.
Part 1 was redone on 9 October: five agents read the whole app (about 75,000 lines, every file of vi-dancer `src/` and koan-shared `vidancer-ui/src`), then I checked every finding in the code myself. Full write-ups with file, line, path and fix idea: `docs/audit-2026-10-09/` (A saving and files, B money, C back end, D editing screens, E generator screens, plus my verdict on each).
This file is the working source for the audit PDF. Nothing here is a fix.

## Part 1. Bugs (full re-audit, 9 October)

**99 bugs: 18 high, 45 medium, 36 low.** 13 of them are unconfirmed: the code path is real, but whether it bites depends on a supplier's behaviour or on timing (marked "unconfirmed"). One agent finding was not real and is left out (an old music-lane gate in export that no project can reach any more).

All 61 existing tests pass. None of them covers the bugs below.

**Batch 1 fixed 9 October** (committed, not installed): the settings fix plus H1, H3, M10, L2, L5, L6, L7. One rule for every file a save builds on (`fileSave.ts` readIfExists): only a missing file is empty, a lock waits, damage or a lock that never lets go refuses the save and leaves the file as it was. Test: `scripts/test-failed-reads.cjs`.

**Batch 2 fixed 9 October** (committed, not installed): H4, H5, H6, H8, H9, H10, H11, H12, M14, L11, L12. One mark, `markProviderAccepted()` (jobNotifications.ts), set at every point a supplier hands back a job id or a paid answer; a marked job that fails is never retried, and the window is told `accepted`, so it is never re-queued and its row never says "run it again". ✕ before the submit stops it there (`assertNotStopped()`), Co-Director stop refuses the rest of the reply, Runway THROTTLED is waited for, a Bridge reply that reads like a job was made is never answered with a resend, fal's own submit re-send on a gateway error is stopped, last session's queue is offered once per project per session and each project's rows go to its own file. Tests: test-fal-submit-once.cjs (new), cases added to test-job-notifications, test-bridge-logins, test-bridge-image, test-queue-failure-browser, test-codir-fire-browser.

**Batch 3 fixed 9 October** (committed, not installed): H7, H13, M4, M12, M17, L8, L9. Video Editor jobs and clip edits now leave a recovery entry the moment a supplier takes them (fal, Higgsfield, Venice; Google's extend has no job id to keep), and recovery lands them as a node or a take the same way the live run does. A Bridge (auto) render sent to Venice is filed as Venice. A local render that finishes after a project switch is filed with its file and added when its project opens. Spend is booked once, in main, in the project that ran the job: live jobs (window and Co-Director plan) in the job wrapper, recovered jobs by recovery; every job carries its estimate (`spend`), and a supplier's own price wins. Enhance holds off the recovery pass while it runs; ✕ in its second stage keeps the first stage's entry; one failed fal image download no longer throws away the other variants. Not booked yet: Co-Director plan Enhance jobs (no estimate in main). Tests: cases added to test-recovery and test-job-notifications.

**Batch 4 fixed 9 October** (committed, not installed): H2, H15, M29, L3, L4. A result that lands in the background (a render's take, an edit's node, a recovered job, a measured length) is no longer an undo step: what it added is put back into any older snapshot undo or redo restores (`project.ts` landings), so Ctrl+Z never takes a paid result away and redo survives it. Switching timelines is no undo step and undo keeps the timeline in view; the switch clears the Clip Monitor's block and the selection. Undo/redo no longer use a global switch a failed save could leave stuck. Image Gen, Image Editor and Video Editor deletes keep the files (Cleanup reclaims them), so "undoable — Ctrl+Z" is true; the Image Editor ✕ and a single Image Gen take delete now ask. Cleanup keeps a live take's reversed copy. Test: `scripts/test-undo-landings.cjs`.

**Batch 5 fixed 9 October** (committed, not installed): H14, M5, M6, L1. A duplicate copies the project and its media but never its run state (an approved Co-Director plan, the queue, recovery entries: `project.ts` copyProjectFolder). Sheet build, cross-project clip import and Assembly Concept / Assemble check that the project that asked is still open before they write, and an import commits into the live project (a Ctrl+Z meanwhile no longer leaves clips only on screen). A Co-Director brief carries the project it was typed in; main refuses it anywhere else, and the box resets when the project changes (the last 600 ms of typing before a switch is not saved). Test: `scripts/test-wrong-project.cjs`.

**Batch 6 fixed 9 October** (committed, not installed): H16, M3, M36, M37, M38, M39, M40, M41, M43, L29, L31. Clip Gen fills its form through one function (clip load, ↩ load Tn's recipe, the empty form after a project switch), so the seed and the links load and restore with the rest and a switch leaves nothing behind. A reload of the same clip (a Co-Director write, an undo) takes only the fields that changed in the store, never the ones being typed; Style Sheet does the same; Effects cancels a pending slider commit only when that block's effects really changed. A pending save goes out on a clip / style / Image Gen switch or panel close instead of being dropped. A new-clip render that lands adopts the typed form (beats included, as does "+ new"). Score length and refinement clamp on blur/Enter; a queued Voice render carries the recipe as pressed; a queued Co-Director message keeps the clip / focus / Image Gen it was typed on; a dropped Watched image joins the Library first; the Sheet Gen name renames on blur/Enter. Not covered: nothing flushes a pending edit when the app window closes. Tests: `scripts/test-forms-browser.cjs` (test:forms-ui), cases added to test-score-browser and test-voice-browser.

**Batch 7 fixed 9 October** (committed, not installed): M8, M24 to M28, M30, M32 to M35, L19 to L27. Timeline writes answer as soon as the change is in memory (the save finishes in its chain), so quick nudges and gestures no longer snap back; insert-audio is one write. A cut (razor, overwrite, head trim) gives each piece the volume envelope it plays and a fade only on its own edge (`audioEnv.ts` envHead / envTail). A head trim keeps linked sound in sync (main `keepRidersInSync`). Lane audio with a speed is drawn, snapped, keyframed and trimmed as it plays. Timeline keys and Ctrl+C/X/V act only while a timeline or the Timeline Monitor is the active panel. A drop lands in the timeline its panel shows; Bin clips drag as their own type; Assembly defers to the docked Timeline Monitor; reversed blocks hand the forward window to the Video Editor and the Clip Monitor plays the reversed copy. Deletes take linked sound along and respect locked tracks; the Clip Monitor trims like the timeline; a volume band drops its selection on an outside press; the effects baker decodes per block; slot adoption finds its timeline; the Image Editor refs take a multi-drag; a sound-only timeline asks before deleting; a lane drop builds from the current timeline. Tests: `scripts/test-timeline-edits.cjs`, a Ctrl+V case in test-timeline-keys-browser.

**Batch 8 fixed 9 October** (committed, not installed): M18 to M23, L13, L18. ✕ on a local job waiting for the GPU (or in the engine's cold start) ends it before it runs (the batch 2 stop list, checked in `runtime.withGpu`); a running local score stops its engine. LoRA folder changes, checkpoint and kernel deletes stop the engine at its next GPU turn, after the running render; ACE / MiniMax deletes stop only their own engine. Not covered by an automated test: M19, M21, M22, M23, L13, L18. Test: `scripts/test-local-engines.cjs`.

**Batch 9 fixed 10 October** (committed, not installed): H17, M11, M13, M15, M16, M42, M44, M45, L10, L28, L30, L32, L34, L35. Watched "send both" hands Image Gen both LoRAs at their weights. A Civitai LoRA of another version with the same file name gets its own folder, and Get + Use picks the right one; a download refused before it starts clears its row. ✕ or the timeout on an ElevenLabs or Google score or voice marks the job taken, and the row says the supplier may still bill. ## Part 3. Workflows, end to end

Sources: `docs/WORKFLOW.md` (the laws), `docs/workflow-audit-2026-07-18.md` (placement law), the public AI-MANUAL (0.26.0), the panel registry (`App.tsx` PANEL_DEFS), the code paths named below, Astra's 05-WORKFLOWS as leads, and the comparison apps listed at the end.

**Correction (10-08, his catch):** the first draft of this part treated takes as versions of one shot to compare and pick a winner. That is wrong. WORKFLOW.md still teaches the old model; that is a doc fix for his list.

**The working model.** Sources (Clip Gen, Image Gen, Score, Voice, SFX, Sheet Gen, the two edit trees) produce **libraries of takes**. Variation is deliberate: he changes settings between takes, or batches 20 variations, to have many different takes to work with. Takes are the material. He marks them (★ flag, colour, disabled, ~ tag) and pulls individual takes out into use: onto the timeline as pinned blocks, into the Bin as new clips, into the Library, into ref slots, onto fields to restore a recipe, into the editors, into the next generation. There is no one right take; selecting one never retires the others. The ★ flagged last is the one dynamic blocks play.

The loop: **make variety → mark it → pull takes out into use → feed them back into the next generation.** Every stage can bounce back to the plan.
