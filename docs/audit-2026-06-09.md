# vi-dancer — Final Audit Report

## 1. Verdict

The architecture is fundamentally sound and the hard problems are already solved well: imperative playhead discipline, isolated tlProgress subscribers, the beats-ownership races (beatsDirtyRef / draftClipRef / partial-merge saves) all hold up under adversarial review. What is NOT sound for the roadmap is the plumbing underneath: persistence is non-atomic and unserialized (real data-loss path), every mutation ships the whole Project over IPC and replaces the whole store reference (effect storms that get worse with every roadmap item), the data model has no schema version and hardcodes a single timeline and a single engine in ~10 call sites, and panels.tsx is a 1,562-line monolith with 4 copies of beat math and 92 inline styles. None of this requires a rewrite — it requires roughly two weeks of targeted hardening BEFORE roadmap work starts, because items 2 and 3 each multiply the cost of these flaws.

## 3. Structure plan

**panels.tsx split** (mechanical, behavior-preserving, barrel re-export keeps App.tsx untouched):

```
src/shared/types.ts                 ← Project/Clip/PromptData/Take/Timeline/ProjImage (single source, main + renderer import)
src/shared/models.ts                ← ModelDescriptor + seedance2/sora2 descriptors (fal.ts + RenderPanel both read)

src/renderer/src/ui/tokens.ts       ← colors/spacing/typography (re-exports styles.css vars)
src/renderer/src/ui/Icon.tsx        ← name→lucide map (emoji fallback until lucide lands)
src/renderer/src/ui/controls.tsx    ← CtlInput/CtlTextarea/Btn/Section (kills the 3 `ctl` copies)
src/renderer/src/ui/PanelErrorBoundary.tsx

src/renderer/src/lib/filmstrip.ts   ← STRIP_CACHE + LRU + ensureStrip/useStrip/sampleStrip
src/renderer/src/lib/beatUtils.ts   ← beatAtTime/beatRefImage/useBeatMetadata/useTrimWindow
src/renderer/src/lib/dragDrop.ts    ← the 6 MIME constants + setDragData/getDragData<T>
src/renderer/src/lib/time.ts        ← smpte, TC_FPS
src/renderer/src/lib/validation.ts  ← validateForm(form, descriptor)

src/renderer/src/panels/Library.tsx      (~80 LOC)
src/renderer/src/panels/Bin.tsx          (~115 LOC)
src/renderer/src/panels/Monitor.tsx      (~240 LOC)
src/renderer/src/panels/SourceMonitor.tsx(~470 LOC)
src/renderer/src/panels/Timeline.tsx     (~300 LOC + TlBlock/Playhead/TimeReadout)
src/renderer/src/panels/index.ts         ← barrel re-export of the 5 panels
src/renderer/src/panels/shared/MentionInput.tsx ← extracted MentionArea, reused by Beats + RenderPanel
```

**Duplication to consolidate:** beat math (4 copies → beatUtils), `ctl` style const (3 copies → controls.tsx), @-mention autocomplete (2 copies → MentionInput), MIME strings (6 files → dragDrop.ts), entity types (2 copies → shared/types.ts). TlBlock drops from 26 props to ~8 by reading clip/take/beat data via a `useTimelineItemData(item)` hook.

**State-ownership rule to adopt:** *Main owns canonical data; the store mirrors it via per-entity deltas, never whole-project replacement. Exactly one panel owns each field's writes (SourceMonitor → beats, RenderPanel → everything else), enforced by what the save payload may contain — not by ref flags. Panels import only store/lib/ui; never App, never each other; panelBus stays one-way App→panels (add eslint import/no-cycle).*

## 4. Fix-before-roadmap list (ordered)

1. **shared/types.ts + schemaVersion + migration scaffold** — blocks roadmap 2 & 3. Every schema change after timelines/engine land pays the dual-definition tax twice. Half a day.
2. **Atomic + queued saveProject, openProject try/catch, settings tmp+rename** (#2, #3, #20) — blocks everything; roadmap 2 multiplies mutation frequency and therefore corruption odds. One day.
3. **Per-entity IPC deltas + store merge** (#4) — blocks roadmap 1 & 2. Splitting panels and adding timelines on top of whole-project replacement bakes the effect-storm pattern into 10 new files. Two days.
4. **media:// path validation + fal credential hygiene** (#1, #5) — blocks roadmap 4 especially (image editor adds more file-path surface). Half a day.
5. **editTimelineIndex reset on timeline mutation** (#6) — blocks roadmap 2; this bug becomes "wrong timeline AND wrong slot" once timelines are plural. One hour.
6. **panels.tsx split + tokens + beatUtils** (#11, #12, #13) — this IS roadmap 1's prerequisite; also makes the timeline refactor (#9) touch 5 small files instead of one monolith. Three to four days.
7. **Model registry skeleton + descriptor-driven RenderPanel fields + validation** (#10, #17) — must precede roadmap 1's restyling of the Clip Editor form, or the form gets rebuilt twice. Two to three days.
8. **STRIP_CACHE LRU + clear-on-project-switch** (#7) — before timelines/stitch multiply filmstrip volume. Half a day.

Items 1-5 ≈ one week. Items 6-8 ≈ one more week and double as roadmap-1 groundwork.

## 5. Roadmap readiness

**1. UI design-system overhaul — YELLOW.** Nothing architecturally blocks it, but doing it inside the monolith with 92 inline styles is doing it twice. Moves: (a) split panels.tsx first (fix #6 above), (b) tokens.ts + Icon.tsx + controls.tsx so lucide is a one-file swap, (c) error boundaries per panel while you're touching every panel registration.

**2. Multiple timelines + stitch/export — RED.** Single-timeline assumption in 7+ paths, no schema versioning, no ffmpeg decision, and the editTimelineIndex bug becomes two-dimensional. Moves: (a) schemaVersion + migration first, (b) `timelines` map + `activeTimelineId` + a single `timeline()` store accessor that ALL call sites go through, (c) decide ffmpeg now — recommend fal ffmpeg-api/merge-videos initially (fits BYO-keys, zero bundle cost), keep a `stitch.ts` interface so wasm can swap in later.

**3. Model registry (Sora 2) — YELLOW.** The store-everything-send-subset design and Partial-merge saves already fit this perfectly; what's missing is the descriptor layer. Moves: (a) shared/models.ts capability descriptors consumed by both fal.ts and RenderPanel, (b) `engine` field on PromptData + `engine`/`durationActual` on Take with load-time default `'seedance2'`, (c) descriptor-driven field rendering + pre-render validation so Sora's no-seed/no-endFrame/enum-duration rules are data, not branches.

**4. Image editor (Nano Banana) — GREEN.** The pattern already exists end-to-end: fal.ts pipeline → file into project dir → Library entry → media:// serving. Moves: (a) land the media:// path validation and fal credential hygiene first (this feature widens both surfaces), (b) generalize fal.ts into per-endpoint modules under src/main/fal/ rather than growing one file, (c) fix the @imageN auto-number collision (project-level imageCounter) before generated images start flooding the Library.
